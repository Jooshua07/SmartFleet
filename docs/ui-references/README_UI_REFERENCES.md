# SmartFleet phone-first design references

These are static concept mockups, NOT specifications for data, validations, currency amounts, or database schema.

Use the consistent navy/white/blue visual style, responsive spacing, cards, navigation and layout.
Use Zambian kwacha (K); no fake example content in operational UI.
Ignore inaccurate mockup examples such as fuel tracking, unsupported statuses, non-Zambian examples, invented dates, bus pictures, model/seating fields missing from schema, and fake financial results. Implement fields only when supported by approved migrations.
Status in current buses table is ACTIVE/INACTIVE; IN GARAGE is a proposed separate operational state and must not be faked without an approved data source.
Mobile bottom navigation: Home | Buses | Finance | More.
Menu quick actions: Record Cashing, Record Expense, Add Bus, Drivers, Reminders.
Add Bus final step for documents/review not depicted and should be designed consistently after schema audit.
